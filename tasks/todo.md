### 補助処理の接続とレビュー

- 圧縮は主会話の SDK に `/compact` を送り、SDK が返す境界と要約を抽出した Claude Code の表示処理へ渡す。
- タイトル生成は SDK の `generateSessionTitle`、補助質問は同じ主会話の `askSideQuestion` に接続した。この SDK 版の実装にある既存機能を使い、生成処理を独自に作っていない。
- 単発生成と会話の振り返りなども SDK の `query` に接続した。任意の履歴を渡す場合の形式変換には、抽出した Claude Code の変換関数を使う。
- 圧縮の保持対象には、画面へ通知されなかった SDK 側のメッセージも含まれる。主会話の SDK の履歴保存を有効にし、SDK の保存ファイルを、抽出した Claude Code の履歴読み込み関数で読む構成に変更した。SDK 公開の `getSessionMessages` は内部の attachment を返さず、そのままでは圧縮結果に含まれる保持対象を揃えられなかった。
- 通常入力は SDK 正式の `client_composed: true` を使い、親で処理済みのファイル参照やコマンドを SDK が再解釈しない。SDK に実行させる `/compact` にはこの指定を付けない。
- ソース 2,695 ファイルの比較では、宣言した接続箇所のある 10 ファイルだけが異なる。画面のコンポーネントには変更なし。
- 実際の SDK 子プロセスと模擬 API で、タイトル生成、通常生成、構造化出力、任意履歴の分岐を確認した。`sdk-completion-probe.json` と `sdk-tool-free-fork-probe.json` に記録。
- 元の画面から履歴を再開し、SDK による圧縮、以前のコードの再回答、`/btw` の別質問での同じコードの回答が成功した。`sdk-compact-persisted-flow.*` に記録。検証中、親の TUI からの直接モデル送信は検知されなかった。
