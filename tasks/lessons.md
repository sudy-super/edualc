# 実装時の確認事項

- 2026-10-17: リポジトリの公開範囲はユーザーの最新の指定に合わせる。sudy-super/edualc は public とし、コミットの作者とコミッターは sudy-super、共同著者の記載は付けない。

- 2026-10-17: 「自動更新」という依頼から定期実行や常駐処理まで広げない。今回の更新操作は `edualc update` に限定し、ユーザーが求めていないスケジューラーを追加しない。

- 2026-10-17: リポジトリとインストールした実行用ファイルを分ける。リポジトリは指定された Documents 配下に置き、起動コマンドをリポジトリへ直接リンクせず、Claude Code と同じ ~/.local/share 配下のバージョン別の実体へリンクする。
- 2026-10-17: 抽出スクリプトを配布するときは、そのスクリプトが子プロセスへ preload する解析用ファイルも含める。インストール先だけで抽出と起動を確認してから起動リンクを切り替える。

- Bun の単一実行ファイルでは、bytecode のほかに JavaScript ソースが残っている場合がある。埋め込みファイルの情報を読んでから逆コンパイルの要否を決める。
- 元の描画エンジンが独自の実行環境に依存する場合は、その依存を実行して確認する。通常配布版の Bun で動くと決めつけない。
- SDK を別プロセスで起動するときは preload の環境変数を除く。同じアプリの再帰起動を防ぐ。
- 承認への回答と通常の下書きを同じ編集状態に置かない。承認要求の到着と取り消しで下書きが消えないことを確認する。
- 疑似端末の検証では、終了を待つ間も出力を読み続ける。端末の出力待ちによる停止をアプリの終了障害と混同しない。
- 疑似端末の検証が失敗した場合も、終了処理に入る前に画面と端末出力を保存する。期待した回答が表示されても、SDKのresultを受け取る前に終了させない。再開した履歴に同じ回答がある場合は、一意な文言で新しい回答を識別する。

- 2026-10-17: 「元の TUI をそのまま移す」という依頼を、低水準の描画部品を使った別画面で代替しない。元の画面を構成するコンポーネントと操作を保持し、元画面との比較を完了条件にする。前回の部品抽出だけで完成とした判断は誤り。

- 2026-10-17: SDK が内部で同じ CLI を使う場合、履歴の再開、設定の読み込み、ツール実行などの既存機能を先に調べる。画面や設定の中継を再実装せず、必要な接続だけを書く。

- 2026-10-17: 画面に最終回答が出ただけでは会話の完了を証明できない。SDK の result と親の履歴保存まで確認する。再開時に元の TUI が補うメッセージも、元の保存関数に通してから SDK の再開位置に指定する。

- 2026-10-17: 会話実行だけを SDK に接続して完了としない。ユーザーが SDK 側への移行を求めた範囲には、圧縮やタイトル生成などの補助処理も含め、親からのモデル呼び出しが残っていないか確認する。

- 2026-10-17: 作業の中心は元の TUI と SDK の接続に置く。画面、圧縮、タイトル生成、会話履歴の意味を独自に再実装しない。SDK の既存処理と元のシリアライズ・表示関数を優先し、接続に不可欠な形式変換以外のコードを増やさない。

- 2026-10-17: 「元の関数」「元の処理」と省略せず、抽出した Claude Code の表示・保存処理なのか、SDK の会話・生成処理なのかを具体的に書く。SDK への接続が残っている箇所を曖昧にしない。

- 2026-10-17: 保存先はユーザーの既存の使い方に合わせる。edualc の設定は Claude Code の ~/.claude と対応する ~/.edualc に置き、独自の接続設定形式を増やさず標準 settings.json の env を使う。

- 2026-10-17: 認証方法だけを変えたい依頼で、接続先やモデルまで分離しない。API キーと資格情報の保存先だけを分け、Claude Code の既存設定・会話履歴はそのまま共有する。

- 2026-10-17: 「API キー以外は本家と共有」という条件では CLAUDE_CONFIG_DIR を変えない。skills / plugins / statusline / mods / settings / 会話履歴は既存の参照先を維持し、資格情報の保存先と起動時に指定する API キーだけを分ける。
